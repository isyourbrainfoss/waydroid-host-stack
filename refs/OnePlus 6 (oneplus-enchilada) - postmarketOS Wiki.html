The OnePlus 6 is a powerful and efficient mobile device, well regarded as portable work horse. Getting mainline Linux working on it means not only freedom from proprietary software, but also continual security patches and the ability to boot any mobile or desktop Linux distro.

After the OnePlus 6 reached End-of-Life by OnePlus in December 2021, running newer Linux kernel versions is the only way to ensure that the device can continue to be safe and usable for years to come. The Snapdragon 845 is still an incredibly capable SoC, likewise the OnePlus 6 is a well-built (bar the notch) and perfectly adequate device. It is abhorrent that OnePlus sent millions of sold units to early death in a landfill (or at best recycling): join us in doing our best to continue to make devices like the OnePlus 6 safe and usable.

The phone is currently capable of booting modern Linux, check the table on the right (or above on mobile) for the hardware support checklist.

Despite being able to run an up to date kernel, we are still dependent on the now aging firmware for features like the bootloader, modem, WiFi and Bluetooth to function. While it is relatively unlikely that a vulnerability is discovered in this firmware, it is absolutely a possibility. Until OnePlus releases the signing keys used to sign new versions of the firmware – allowing us to potentially make use of future security patches — we're stuck with what we've got.

Flash mode

To place the device info flashing mode, unplug the USB cable and hold Power and Volume Up until you see a screen showing the word START and information about the device.

For the OnePlus 6T, hold Power and both volume buttons.

If you're struggling to enter fastboot, ensure that you have unplugged the USB cable and do not release the button combination until after the START text appears on screen

Troubleshooting

If you encounter issues flashing with fastboot getting stuck or displaying weird errors, such as device does not support slots, use one of the following workarounds:

  • Once the device is in fastboot mode, unplug it, run your fastboot / flasher command and wait for the "<waiting for device>" message, then choose the "reboot bootloader" option on the device, press the power button to select that option and plug in the device while it reboots.
  • Prepare the fastboot flash command in your terminal, on the device choose the "reboot bootloader" option from fastboot, press the power button to confirm and then run the command while the device reboots. You'll see a "waiting for device" message in your terminal, the flashing should start as soon as the device gets back into fastboot mode.

Installing

The bootloader is the only firmware that postmarketOS doesn't install itself, all other firmware (devicetree, GPU, modem etc.) is supplied by postmarketOS. In contrast to custom Android ROMs, it is incredibly unlikely that any bugs or issues you encounter are caused by whatever OS you previously had installed on the device.

Prerequisites

Upgrade

Before installing postmarketOS, it's recommended that you upgrade your device to the latest release of OxygenOS (OnePlus's version of Android) on both slots[1]. Try this first if you encounter issues with fastboot.

If you have a very old version of OxygenOS (for example after using the "MSM Download tool" for android 10), you probably need to update twice, because the device uses A/B partitioning).
First do a normal update, then download the latest version of OxygenOS OTA signed zip, upload it to the /sdcard directory on the phone using adb push <path to update>.zip /sdcard/, go to Settings > System > System updates and do a local update (via the cogwheel) of the latest version again (source).
The latest OxygenOS version (11.1.2.2) can be downloaded directly from Oneplus's update servers 6 6T. Alternatively check this XDA thread for 6 and this one for 6T

Unlock the bootloader

Before installing postmarketOS you have to unlock your bootloader. For the T-Mobile version of the device in the US, refer to Google for guides on obtaining an unlock code. If your device is not carrier locked, the following is all that's needed to unlock the bootloader:

  1. Open Settings, go to "About" and tap on the "Build number" box ~10 times until the "You are now a developer" toast message appears.
  2. Go back to the main settings page, go to "System" and then "Developer options" (it might be hidden behind a dropdown menu). Toggle the switch to "Enable OEM unlocking".
  3. Refer to "#How to enter flash mode" above to get into fastboot mode, then re-attach your USB cable. Run the following command on your host: 
    $ fastboot oem unlock

    If you see < waiting for any device >, try running as sudo and restart your device into fastboot mode again by selecting "Restart Bootloader" on the device.

  4. Read the message displayed on your device screen. Once read, confirm the unlock if you're willing to proceed. THIS WILL ERASE YOUR DEVICE'S INTERNAL STORAGE.

All done! You can now continue with this guide.

Installing pre-built images

Web flasher

You can use the postmarketOS web flasher to flash a prebuilt image of postmarketOS onto your device. Follow the instructions on the page.

Web installer only works on Chromium based browsers. Web installer does not work with Firefox or Firefox based browsers like Librewolf and Mullvad.

Manual install

You will need a computer with fastboot. This can be obtained by installing the android-tools package on Linux or by installing the Android SDK Platform-Tools on Windows, Mac (or Linux).

Follow the installation article to download image files, note that the device code-names are oneplus-enchilada for the OnePlus 6 and oneplus-fajita for the 6T.

Once downloaded, decompress the files with unxz. On Windows you can use a tool like 7zip.

Finally, use fastboot to flash:

Erasing the dtbo partition will make Android (and ALL Android-based software like Ubuntu Touch or TWRP recovery) unbootable on the current slot (read this page if you're not sure what that means). You can re-flash an Android ROM via fastboot by extracting the payload.bin from the OTA zip and using a tool like android-ota-payload-extractor to get the individual partition images, or following sizzlinfajita’s write-up on the XDA forums. It is almost never necessary to resort to extreme measures like "MSM Download tool" to reflash the device via EDL.
If you are using Arch Linux and getting errors like std::out_of_range. Uninstall android-tools and install android-sdk-platform-tools from the AUR[2][3] or build and flash your own build with pmbootstrap 
$ fastboot erase dtbo
$ fastboot flash boot [the file that ends in -boot.img]
$ fastboot flash userdata [the other file]

If you see < waiting for any device >, try running as sudo and restart your device into fastboot mode again.

It can be effective to run fastboot reboot after each command succeeds, to avoid above "waiting for device" connection problem.

WARNING: Do not reboot via the power button on the device! This can result in not all data being properly written to storage, corrupting the rootfs and resulting strange behaviour like postmarketOS getting stuck during boot!
Always use fastboot reboot after flashing.

Installing with pmbootstrap

The vendor is OnePlus, the codename is "enchilada" for the OnePlus 6 and "fajita" for the OnePlus 6T.

Follow the pmbootstrap article, until you have done the install action. 

$ pmbootstrap install --fde # With FDE (it stands for Full Disk Encryption)
$ pmbootstrap install # Without FDE

Reboot back into flash mode as explained above. (If you encounter weird behaviour like the command getting stuck before the flashing starts, reboot into flash mode or select "Restart Bootloader" on the phone itself)

WARNING: Do not reboot using the power button on the device! This can result in not all data being properly written to storage, corrupting the rootfs and resulting in strange behaviour like postmarketOS getting stuck during boot!
Always use fastboot reboot after flashing.

Then flash with 

$ pmbootstrap flasher flash_rootfs
$ pmbootstrap flasher flash_kernel
$ fastboot erase dtbo

If you have flashing or booting issues, try flashing the latest version of OxygenOS to the slot you want to install postmarketOS to (i.e., flash the ROM using TWRP from your other slot). If you still have no luck, try flashing OxygenOS 9, as the bootloader can be more forgiving.

Upgrading firmware without Android installed

When you install postmarketOS and all you get is just blank screen after a reboot or you have some other problems it is possible that firmware was not upgraded. Follow these steps to upgrade firmware. Sadly, the official OnePlus download link does not work as of now. Newest firmware can be downloaded using a spare android phone and Oxygen Updater.

  1. Extract payload.bin file from zip you downloaded
  2. Extract firmware with payload-dumper-go or payload_dumper: 
    $ payload-dumper-go payload.bin
  3. Enter fastboot mode
  4. Unlock partitions for flashing: 
    $ fastboot flashing unlock_critical
  5. Update firmware: 
    for partition in abl aop bluetooth cmnlib cmnlib64 devcfg dsp fw_4j1ed fw_4u1ea hyp keymaster LOGO oem_stanvbk qupfw storsec tz xbl xbl_config; do
    fastboot flash ${partition} ${partition}.img
done
fastboot flash --slot=all modem modem.img
  6. If you are not able to write via fastboot even after unlock_critical, use edl mode instead (turn off phone, push volume +/- and plugin the usb cable): 
    $ edl w abl_a abl.img

    and so on with all the mentioned files.

The list of issues & hacks

In no particular order.

Audio in calls

Call audio should work with the pipewire audio server since the v26.06 stable release with user interfaces such as Phosh. Pulseaudio also works, but is not recommended for new installs.

If you experience audio issues, take a look at #3320 and #3245 for workarounds for specific configurations of audio server, user interface, and init system (systemd or OpenRC). If you seem to experience a different issue from one already open, please report it in a new issue or join the postmarketOS audio matrix channel to discuss.

Mic and speaker with Pipewire

While Pipewire sounds promising for the long run, there are currently some issues with the speaker and microphone.

There is a workaround as of March 2026.

  1. Remove the asound state file as the blog post says.
  2. Then create a file with the following content: 
    # rm /var/lib/alsa/asound.state
# tee /usr/lib/systemd/system/alsa-restore.service.d/override.conf << EOF
[Unit]
ConditionPathExists=!/dev/null
EOF
# reboot

Tri-state key support

The next step is to write hkdm configs for it but this may need to wait for the driver to get upstreamed. hkdm itself needs support for EV_SW devices added.

If you use Phosh with systemd, the tri-state button works out-of-the-box (pmaports!5969), although it is hardcoded to control feedbackd and cannot be easily reconfigured.

Wake from calls and SMS

For this to work, your ModemManager version has to be 1.24.2-r4 or newer. The phone will wake up from any modem event since this is still WIP. Basically, you'll get a little bit more battery life, but your phone will sometimes wake for no reason at all. Due to this, it is recommended to set the automatic suspend time to 1 minute. There are slight issues, very rarely, when answering a call, "Dummy output" appears as the default sink.
  1. Verify that your ModemManager version matches the one described above: 
    $ apk list modemmanager
  2. Open ModemManager's service file for editing: 
    # systemctl edit ModemManager.service
  3. Write 
    ExecStartPre=/bin/sh -c "echo enabled > /sys/bus/rpmsg/devices/4080000.remoteproc:glink-edge.IPCRTR.-1.-1/power/wakeup"
ExecStart=/usr/sbin/ModemManager --test-quick-suspend-resume

    above the line containing ### Edits below this comment will be discarded.

  4. Save the file and reboot.
  5. The phone should wake up from modem events from now on.

OTG doesn't work

"OTG" (USB-C role switching to host mode) is blocked on USB-C power delivery support in the charger driver. Host mode can be forced by modifying the DTS when building a kernel, but it isn't clear what this fixes or may break.

See this matrix post by User:Kcxt:

no, OTG isn't really a thing anymore anyway - it's technically specific to micro USB, usb-c has role-switching where a device can either be a host device or a peripheral device. Right now we force peripheral mode always. Once support for the full USB-C power delivery system is implemented in the charger driver, we can negotiate a role with the other device, e.g. if it's a powered dock we want to charge but also be the host device.

Once that's done we can implement DP alt mode on top which requires talking to the dwc3 driver I think, and configuring some external orientation switch for the USB SBU pins which are directional and required by displayport

that's all the missing pieces, that will give us displayport on the SHIFT6mq, neither the Pocophone F1 nor OnePlus 6 support DP alt mode

The phone won't supply its own power, so you need either a powered hub or an extension cable wired up to 5v. Some hubs may refuse to work without power being supplied from the port however.

Host mode can be enabled by Dts method and Sysfs method.

Dts method

Install dtc and decompile the appropriate file for you device like so: 

# apk add dtc
# cd /boot/dtbs/qcom
# dtc sdm845-oneplus-<model>.dtb -o temp.dts

Now change dr_mode from "peripheral" to "host" in temp.dts file, recompile it and run mkinitfs to regenerate and flash the boot image: 

# sed -i 's/peripheral/host/g' temp.dts
# dtc temp.dts -o sdm845-oneplus-<model>.dtb
# mkinitfs
# reboot

To revert the changes just do the same thing again but with 's/host/peripheral/g', kernel updates will also revert it.

Sysfs method

Change "device" to "host" in "/sys/kernel/debug/usb/a600000.usb/mode" : 

# echo host > /sys/kernel/debug/usb/a600000.usb/mode

To revert the changes just do the same thing again but change host to device or reboot the device.

Verify

Run the command as below to verify: 

# cat /sys/kernel/debug/usb/a600000.usb/mode

If the command return host then congratulation you have enabled the host mode successfully.

QUALCOMM CrashDump Mode

Some users experience the device crash and land on a screen that says "QUALCOMM CrashDump Mode." If this happens, you can reboot the device by holding down the power button for about 10-15 seconds.

It is not fully understood what types of events trigger this crash screen, and information reported can be useful. When the device shows this screen, a computer can be used with the tool EDL to collect the full RAM dump and extract logs. Reporting this information on gitlab can help identify and resolve these issues.

For example, a known issue is that some users experience increased frequency of crashing on boot when a SIM card is inserted into a OP6T (#4199).

Another user had frequent crash dumps which disappeared after upgrading to the latest firmware (OxygenOS) and re-flashing postmarketOS (#4677).

GPS

WARNING: To use and test GPS functions, make sure a SIM card is inserted (mmcli v1.22.x), GPS is enabled in mmcli, geoclue is executed. Then disable suspend, go outside for 15min. until you get a fix

Carefully read Troubleshooting:GPS for more details on how to activate the GPS using ModemManager's CLI and enabeling Geoclue.

WiFi

Unlocking Wi-Fi channels

The WiFi firmware appears to default to US regulatory rules. Therefore, the device will ignore channels 12 and 13 of the 2.4 GHz band, as they are not permitted in the US. If your access point makes use of channels 12 and 13 you may experience seemingly random connection issues. Some access points have a setting for this.

You can try changing the regulatory region, but this doesn't always work without patching the firmware. To build and install a custom board-2.bin file, run the following commands on your OnePlus 6. Make sure to replace IT with your country code. 

$ git clone https://github.com/M0Rf30/wcn3990-regdomain && cd wcn3990-regdomain
$ ./gen-bdf.py list-countries # prints all 131 supported alpha2 codes
$ ./gen-bdf.py generate --base base/board-2.bin --mode variant --variant oneplus_sdm845 --chip-id 30214 --regdomain IT -o board-2.bin.oneplus-enchilada.IT
# zstd board-2.bin.oneplus-enchilada.IT -o /lib/firmware/ath10k/WCN3990/hw1.0/board-2.bin.zst
# echo '!lib/firmware/ath10k/WCN3990/hw1.0/board-2.bin.zst' > /etc/apk/protected_paths.d/ath10k-custom.list

Then reboot your device. To verify the changes, print the regulatory region with iw reg get. Now the country code of phy#0 should be your chosen one instead of US.

2.4 GHz

2.4 Ghz WiFi may have occasional problems. The whole modem goes offline at irregular intervals (minutes to weeks after a fresh boot).
See: #3486

5 GHz

Connecting to a 5 GHz network may fail with denied association (code=18)[4], which is most likely caused by the regulatory region issue described above.

If you have both a 5 GHz and a 2.4 GHz network and the 2.4 GHz network just happens to be using channels 12 or 13, the device will silently fail to connect.

Monitor Mode

Switching to the WiFi Monitor Mode requires reloading the driver with frame_mode=0 and enabling raw mode in firmware-5.bin. The commands to do this can be found here: [1]. Packet Injection however doesn't work.

Hotspot

In case you having issues with connecting to the WiFi Hotspot, consult WiFi#Troubleshooting

TrustZone

Drivers to communicate with the QSEE (Qualcomm Secure Execution Environment) are not on mainline and you can't flash OP-TEE because XBL_SEC checks the signature. Those drivers are called QSEECOM in the CAF kernel but there is the need to standardize them using the generic interface defined in include/uapi/linux/tee.h. You can use the OP-TEE implementation as an example. More documentation here https://www.kernel.org/doc/html/latest/tee/op-tee.html.

Having a TrustZone is useful to do a lot of things related to security, but mainly fingerprint management, secure encryption involved in NFC, useful to emulate contactless smart cards, and Widevine L1 to watch premium streaming services with the best resolution!

Regarding DRMs and userland, on Waydroid or Android mainline you need to develop oemcrypto.so with the support of the standard API for the TEE; manufacturers implement it with their custom interfaces. Look at this https://source.android.com/devices/drm#drm-plugins.

On GNU/Linux, you need to implement/enable Widevine L1 on players. For example on Firefox, if you want to watch Netflix or other in-browser streaming services, but you might also want to use an extension like https://github.com/lkmvip/netflix-4K-DDplus to spoof the device and so make Netflix give you the encrypted stream. Another good implementation opportunity is on FFMPEG/VLC, it would be cool to make VLC able to stream Netflix and also having the possibility to save decrypted streams.

Battery/Power

While battery and charging are working, we sometimes get inaccurate power percentage values reported. In particular, if you have a replacement battery in your device, the BMS (battery management system) chip may differ from the original one, and the battery indicator may always show 100% and charging. In this case, the following might help:

You will decompile/edit/recompile your device tree blob (.dtb) file. Add the dtc package: 

# apk add dtc
$ cd /boot/dtbs/qcom
# dtc sdm845-oneplus-enchilada.dtb -o temp.dts
# sed -i 's/bq27441/bq27541/' temp.dts
# sed -i 's/bq27411/bq27541/' temp.dts
# dtc temp.dts -o sdm845-oneplus-enchilada.dtb

Then run mkinitfs to incorporate the changes into your initramfs: 

# mkinitfs

Charging on variable powersources like solarpanel/dynamo does not work as expected.

Modem bugs

The recent enablement of ModemManager enables SMS and mobile data to work on supported SDM845 devices including the OnePlus 6 and 6T. It isn't possible to test these extensively due to the number of region specific and carrier specific issues that could arise.

If you're encountering modem issues, perform the following steps to collect logs and submit them so that I or someone else can review:

On your device with SIM card inserted: 

# systemctl stop ModemManager # If running systemd
# systemctl restart msm-modem-uim-selection # If running systemd
# service modemmanager stop # If running openrc
# service msm-modem-uim-selection restart # If running openrc
# ModemManager --debug 2>&1 | tee mm.log

If your device requires SIM unlocking, perform that in Phosh settings, wait for a few seconds and then stop modemmanager again.

Create a new issue in ModemManager here to explain your issue, include a link to a pastebin containing the logs you captured (they're in mm.log in your home directory on device). At the bottom of your issue add Cc: @Kcxt so that I'll be notified.

Please also include the output of uname -a and sudo qmicli -d qrtr://0 --uim-get-card-status in your issue.

SIM not appearing

Some SIM cards or modem firmwares might take longer to initialize. If the SIM card does not appear, but sudo qmicli -d qrtr://0 --uim-get-card-status shows that the card is present (Card state: 'present'), one possible solution is to increase the wait time for the SIM card to appear after starting the modem. Edit the file: /etc/conf.d/msm-modem-uim-selection and change: sim_wait_time=1 to sim_wait_time=30 and reboot.

Dual Sim

Some users have reported issues with dual SIM causing modemmanager issues, whilst modemmanager should automatically select the first SIM, it lacks proper dual SIM support and sometimes can get confused. Currently the best workaround is to make sure you only have one SIM card inserted; if you get errors unlocking the SIM, try putting the SIM into the other slot (and reboot?). See also Issue 3531.

VoLTE

WARNING: VoLTE support is experimental.

VoLTE support is provided by the 81voltd service, and should work with the pulseaudio and pipewire audio server, with pipewire being the recommended choice. On the OP6/OP6T, 81voltd should automatically enable VoLTE if supported by the carrier.

If you experience issues with VoLTE, take a look at #1878 and #3713. If you experience a different issue from one already open, please report it in a new issue or join the postmarketOS audio matrix channel to discuss.

Pre postmarketOS flash steps (increases chances of working)

These steps increased the probability of working VoLTE on fajita (should apply to enchilada, too.) These worked for me as of October 2025 on Vodafone UK and O2-UK. YOUR MILEAGE MAY VARY!

First, flash the following version of OxygenOS 9 for your device, 9.0.8 for enchilada, and 9.0.16 for fajita. you will want to do this with msmdownloadtool.

If you are coming from postmarketOS, you may find that when you use msmtool your device only shows 16GB of UFS in android instead of 128gb, to fix this enable oem unlocking, boot into fastboot, unlock the bootloader and let the unlock wipe the device, then immediately reboot into fastboot and issue 
fastboot erase userdata
then boot recovery and do another wipe

Now, unlock your bootloader and boot into android, set up the device. sideload engineermode and oneplus logkit onto the device then use dialer code 

*#800#`

and select to run with engineer mode. go under oneplus logkit -> feature switch and toggle on both VoLTE and VoWiFi. Reboot the device and insert a SIM NOW and test that VoLTE and optionally VoWiFi work in android (the latter won't work in postmarketOS but it is good to test.) Once you have done this, flash postmarketOS in the normal way (I used pmbootstrap to build an image, but prebuilt images should work fine, too.)

postmarketOS steps

The steps below are for the postmarketOS side of things as VoLTE is not enabled by default.

VoLTE support is provided by the 81voltd service.

To test on your device, run the following: 

# apk add 81voltd
# rc-update add 81voltd default # If running OpenRC
# systemctl enable 81voltd # If running systemd

then go into your settings and under your UI's Mobile Network settings, set your network mode to include 4G. Then, restart your device.

After your device boots, 81voltd will not find your modem, so you will have to restart it. First, check your settings to make sure your network mode still includes 4G. If not, set it, then turn mobile network off and on.

Then, run the following: 

# rc-service 81voltd restart # If running OpenRC
# systemctl restart 81voltd # If running systemd

Wait about a minute and you should be able to call. For the least bugs, it is recommended to use Pipewire instead of Pulseaudio for calling. If you are using Pulseaudio (or do not know), run the following and reboot: 

# apk add postmarketos-base-ui-audio-pipewire

If you still don't have VoLTE

After all this, there is a chance that VoLTE may still not work, but there are other things to try. On my first flash I could not get VoLTE at all on neither O2-UK or Vodafone UK. I have found the following to trick it into working, this however is a workaround, so should be mainly used for testing:

first, list your device's profiles with 

$ qmicli --device=qrtr://0 --pdc-list-configs=software

and find the configuration that pertains to you. On my device, configuration 1 is UK-VoLTE-Vodafone, configuration 2 is Telefonica_UK_Commericial (this is O2-UK), and configuration 25 is H3G_UK_Commercial. These are the UK VoLTE profiles to give an example.

Pick your carrier from the output, in my case I will be using O2 as my example and take its ID. It should look similar to this: 

B9:A7:BA:8E:48:66:4A:F1:B9:2F:43:B8:69:FC:F2:6A:EB:FD:09:38

Next up, pick another profile to load first, it can be any of the ones listed by the output of the command we ran earlier and take its ID too.

Lastly: we want to first load the undesired profile, this is done by running 

$ qmicli --device=qrtr://0 --pdc-activate-config=software,undesired_id_here

Now wait 20 seconds and run the same command but with your desired profiles ID. Attempt to make a call from the device or recieve a call to the device. accept the call then through the terminal you can use mmcli -m 0 while on the call and see if it lists LTE as access tech (this is to account for the top bar icons possibly not updating fast enough, this only really should be an issue on sxmo).
